# Marketing Inputs

## Homepage hero raw material

**Supported factual angle:** "Local-first Jira flow analytics for Scrum Masters."

Supporting copy can say: "Analyze Jira CSV exports and Time in Status data to understand Cycle Time, SLE, throughput, WIP aging, bottlenecks and data quality before your next team conversation."

## Main customer problems

- Jira has data, but Scrum Master decisions need flow insight.
- SLE and Cycle Time are hard to explain without clear visuals.
- Time in Status exports are noisy and easy to misuse.
- Teams need presentation-safe metrics, while Scrum Masters need deeper diagnostics.
- Data quality issues can make metrics misleading.

## Product benefits

- Turns Jira exports into working-day flow metrics.
- Separates Team view from Scrum Master diagnostic view.
- Shows SLE percentiles and Cycle Time scatter.
- Highlights WIP risk, bottlenecks and stale work.
- Makes missing data and metric blockers visible.
- Keeps data local in the current implementation.

## Feature descriptions

- **Team view:** compact metrics for team conversations.
- **Scrum Master view:** deeper diagnostics for coaching and workflow improvement.
- **Cycle Time and SLE:** percentile-based delivery expectation from completed work.
- **Time in Status:** queue and bottleneck diagnostics from Jira changelog-derived CSV.
- **Data Monitor:** shows source data gaps and metric prerequisites.
- **Jira pull CLI:** pulls issue and changelog data into local CSV files.

## Possible differentiators

- Local-first data handling.
- Explicit data quality checks.
- SLE based on Cycle Time and working days.
- Presentation and diagnostic modes in one tool.
- Moved Jira issue handling via previous keys/project entry.
